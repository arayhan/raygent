description: Wrap up session — update state, append progress if decisions were made, and commit
allowed-tools: Bash, Read, Write, Edit, Grep, Glob
---

Wrap up the current session by updating documentation and committing changes.

1. **`docs/STATE.md`**: Overwrite the header block with current status:
   - `Phase`: current phase number and name
   - `Next up`: next task id
   - `Blocked on`: current blocker or `nothing`
   - `Last session`: date + 1-sentence summary of what shipped
   - `Verify`: actual outcome of running `/verify` (e.g. `passed (3/3 checks)`), never an assumption
2. **`docs/PROGRESS.md`**: Append **one single line** in the format `[date] [role] [what] [why]` (matching the existing format of the file) **only if** architectural/design/scope decisions were made during this session. A session with no decisions gets no progress line — do not log routine coding activity.
3. **Ideas & Parked items**: Put ideas that arose mid-work into `## Parked` in `docs/STATE.md`, not in code comments.
4. **Lessons**: If a repeatable lesson or rule was learned, record it in `docs/LESSONS.md`.
5. **Commit**: Commit following `docs/rules/git-workflow.md`. **Do NOT push.** Do NOT include any attribution trailers (`Co-Authored-By`, `Generated by`, AI footers).
6. **Print handoff**: Print a concise 5-line handoff summary:
   - `Shipped`: <summary of what was completed>
   - `State`: <current state status>
   - `Next`: <next task up>
   - `Watch out for`: <gotchas or caveats>
   - `Parked`: <parked items or none>

Do not congratulate, do not summarize summaries, and do not re-explain code.
